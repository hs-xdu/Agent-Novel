# 拾光 小说写作助手

基于 Python、PySide6、Pydantic 和本地 Markdown/JSON 快照的小说写作工作台。支持多项目、设定与三级大纲、章节草稿与定稿、选中段落改写、长期记忆和 Markdown 导出，保留 NiceGUI 网页兼容入口。

## 桌面版（当前推荐入口）

主界面已迁移为 **PySide6 原生桌面窗口**，不需要浏览器、18765 端口或本地 HTTP 服务。现有 projects/ 小说数据继续使用，生成、定稿和记忆规则保持一致。NiceGUI 网页入口保留用于兼容及回归测试。

在本项目目录双击 **启动拾光.cmd**，即可打开桌面版。也可以执行：

```bat
cd /d E:\Agents\Agent_Novel
.venv\Scripts\python.exe -m app.desktop
```

初次安装依赖请使用 `uv sync --locked`。桌面版与旧网页版不能同时写入同一数据目录；如果提示占用，先关闭旧实例。

点击窗口右上角 **大模型 API 设置**，可以直接修改运行模式、接口协议、API 基础地址、模型名称、密钥和超时：

- 现有 `.env` 会在首次使用时读取。保存后以桌面设置为准，无需重启或修改 `.env`。
- Responses 模式需要支持 Responses API 和结构化输出；Chat 模式需要支持 OpenAI 兼容 Chat Completions 和 JSON Object，程序会额外进行 Pydantic 校验。厂商与地域不同，密钥和地址不能混用。
- “OpenAI 地址”和“千问北京地址”按钮只填写地址，不改动密钥和模型。千问原有 Responses 配置可继续使用。
- “测试连接”会用当前填写值测试文本及结构化输出，可能产生少量 API 费用；测试不会自动保存。“保存并应用”后下一次任务立即使用新设置。
- API 密钥以密码形式显示，保存至 Windows 系统凭据库；`.desktop/model.json` 只存非密钥配置。凭据库不可用时会提示失败，不回退到明文保存。原 `.env` 仍保留，请自行妥善管理。

四个工作区分别为项目管理、设定与大纲、章节创作和小说记忆。操作顺序与下文相同。AI 任务在后台线程运行，任务进行中允许切换标签查看，但暂时禁用编辑，防止过期结果覆盖内容；任务结束后恢复。关闭窗口时如有任务，会提示等待完成，不会直接强制终止写入。

### 一页式章节创作（当前流程）

首次确认基础设定、全书和当前分卷大纲后，日常创作均在“章节创作”完成：

1. 点击左侧“开始第 N 章”。程序自动编号、建立章节并沿用当前分卷；有未完成章节时按钮显示“继续第 N 章”，不会重复建立。已有章节也可从左侧列表选择。
2. 在“本章规划”查看分卷目标、前章摘要与结尾、计划目标，填写本章额外要求；设置章节大纲长度与详细程度，点击“生成 / 重写本章大纲”。无需先保存空章节。
3. 编辑候选大纲，点击“确认大纲，生成正文”，确认后自动保存正式大纲并生成正文草稿，切换到“正文审阅”。大纲与正文在同一个章节工作区内处理。
4. 编辑正文、选段改写或整章重写，满意后“确认定稿并更新记忆”。正式正文先保存，再整理记忆。成功后可开始下一章。
5. 如果记忆失败，页面明确显示“正文已保存，记忆整理未完成”及原因。点击本页“重试整理记忆”即可继续，无需重新定稿；未同步前暂停章节大纲和正文的 AI 生成，仍可查看与手动编辑。

左侧可设置本次规划章数（1～30），点击“AI 建议本卷章节清单”，随后“审阅并建立章节清单”。清单包含连续编号、名称与目标，可编辑后确认；确认之前只保存候选，不建立章节或改动正式记忆。确认后建立待创作章节，不覆盖已有章节。计划数量可按阶段逐步增加，不必预先确定全书所有章节。

点击“规划下一卷”可前往下一卷大纲；确认后回到章节页，将分卷号改为新卷号再开始下一章。分卷由用户决定，不因达到预估章数自动结束。

章节大纲会读取前章摘要和必要的结尾，正式生成读取已确认设定与大纲。记忆提取使用单独上下文，保留完整定稿正文和必要设定、人物与伏笔，移除无关全书/分卷大纲；在发送前把正文、指令和结构化 schema 一并计入预算，只按剩余空间补充历史摘要。正文和必要资料本身超预算时明确保留正文并提示，不反复发送相同的失败请求。

桌面界面使用左侧工作区导航，右侧集中编辑。点击顶栏“新建小说”输入项目名；当前项目、定稿数量和记忆状态显示在页面标题下方。章节页分别提供“本章规划”和“正文审阅”，把大纲与正文按步骤分开显示。

“设定与大纲”左侧提供“目标字数”和“详细程度”，右侧编辑候选结果并查看实际字符数。全书大纲默认 1000 字、简明；分卷默认 800 字、标准；章节默认 400 字、详细。可在 200～6000 字之间调整。简明只写核心节点，标准增加因果与冲突，详细补充人物动机与伏笔；三种模式都遵守目标字数和各级大纲职责，全书大纲不逐章展开。每份大纲的设置分别保存，未生成时也能通过本地编辑缓存恢复。目标字数是提示词约束，实际输出可能有偏差；缩短目标有助于减少输出量，但不能保证不会发生网络超时或模型思考超时。

设定和章节的未提交编辑会在约 1.5 秒后、切换项目/文档/章节及关闭窗口时写入 `projects/<id>/desktop-drafts.json`，重新打开项目自动恢复。这是编辑缓存，不会确认设定、定稿正文或更新记忆。正式数据仍需点击相应保存/确认按钮；生成失败后可以修正配置并重试。

启动异常和任务错误类型保存在 `logs/desktop.log`，不记录密钥或小说内容。桌面窗口不依赖本聊天执行会话中的 Web 预览。

Windows 分发包构建命令：

```powershell
uv run pyinstaller --noconfirm --distpath release Shiguang.spec
```

将生成的整个 `release/Shiguang/` 文件夹放到可写目录，双击 `Shiguang.exe` 使用。需要携带现有小说时，在关闭旧程序后复制 projects/ 到该目录。不要只复制 exe，也不要打包 `.env` 或密钥。首次启动仍需在软件内配置模型。原始小说目录和构建包数据目录相互独立，不会自动迁移。打包配置会排除 Conda 的同名 ICU DLL，使用 Windows 系统 ICU，避免 Qt 启动时符号不匹配。

桌面自动化测试：`uv run pytest tests/test_desktop.py -q`。无显示环境可设置 `QT_QPA_PLATFORM=offscreen`。

## 启动

需要 Python 3.12 或更高版本，以及 uv。Windows 上若默认 python 是旧版，请通过 `py -3.12` 创建虚拟环境。

```powershell
# 已安装 uv 时
uv sync --locked
uv run python -m app.init_env
uv run python -m app.main
```

若尚未安装 uv，可采用项目内安装方式：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install uv
.\.venv\Scripts\uv.exe sync --locked --python .venv/Scripts/python.exe
.\.venv\Scripts\python.exe -m app.init_env
.\.venv\Scripts\uv.exe run python -m app.main
```

打开 [本地工作台](http://127.0.0.1:18765)。应用只监听本机地址，同一数据目录只能启动一个实例。停止运行可在终端按 Ctrl+C。

配置初始化命令同时适用于 CMD 和 PowerShell：仅在 `.env` 不存在或为零字节空文件时复制模板，已有非空配置会保留。在 CMD 中逐行执行以下命令即可初始化并打开配置：

```bat
cd /d E:\Agents\Agent_Novel
.venv\Scripts\python.exe -m app.init_env
notepad .env
```

`Copy-Item` 是 PowerShell 命令，CMD 不支持。如果模板复制失败，直接运行 `notepad .env` 可能打开或创建空文件。确认文件名为 `.env`，不要保存为 `.env.txt`。

默认端口为 18765，避免与已有的 8080 预览服务混淆。若配置的端口被占用，启动会明确报错，请修改 `.env` 中的 NOVEL_PORT。可访问 [应用身份检查](http://127.0.0.1:18765/api/health)，确认返回的 app 是 `novel-agent`；如果页面出现 ROP 等其他项目，请核对地址和端口。

也可用 `python -m pip install -r requirements.txt` 安装运行依赖；测试依赖由 uv 的开发依赖组管理。

## 模型配置

编辑 `.env`：

```dotenv
NOVEL_MODE=openai
OPENAI_API_KEY=填写自己的密钥
OPENAI_MODEL=填写账户可用且支持Responses与结构化输出的模型名称
OPENAI_BASE_URL=https://api.openai.com/v1
```

当前适配器采用 OpenAI 官方 Python SDK 的 Responses API，正文用 create，设定与记忆用 parse。自定义 API 地址必须支持这些接口，只有 Chat Completions 兼容接口的服务不能直接使用。本项目不预设账户可用模型；需要自行配置并验证。[官方 Python SDK](https://developers.openai.com/api/reference/python)、[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)

未配置密钥时，可将 `NOVEL_MODE=demo` 后启动。界面会明确显示离线演示标识，所有生成内容是固定示例，仅用来体验流程，不能作为真实创作质量的判断依据。实际创作前建议另建项目。

可选环境变量：

| 配置 | 默认值 | 用途 |
|---|---|---|
| NOVEL_DATA_DIR | projects | 小说数据目录 |
| NOVEL_PORT | 18765 | 本机服务端口 |
| NOVEL_TIMEOUT | 120 | 单次模型请求超时秒数 |
| NOVEL_CONTEXT_TOKENS | 24000 | 总上下文预算，需适配所选模型 |
| NOVEL_OUTPUT_TOKENS | 6000 | 输出预留与请求输出上限 |

上下文使用 cl100k_base 的 token 数乘以余量系数估算，不能替代各厂商的精确计数。首次使用 tiktoken 可能需要联网下载编码资源。程序优先保留正式设定、当前大纲、人物和未回收伏笔，历史摘要及检索片段按剩余空间加入。目标字数与 token 上限是两个不同约束，实际字数显示在编辑器下方。

## 使用流程

1. 创建小说项目，在“项目管理”填写题材、简介、目标读者、叙事视角、风格和字数，保存。
2. 在“设定与大纲”生成基础设定，审阅 JSON 内容后点击“确认生效”。也可自行填写合法 JSON。characters 的 relationships 填人物 ID，势力和人物 ID 应保持稳定。
3. 依次生成并确认全书大纲、分卷大纲。切换文档类型后，卷号字段用于选择分卷。
4. 在“章节创作”选择章节编号并点击“加载章节”，填写章节名称和所属分卷，先保存章节信息。
5. 回到“设定与大纲”，选择章节大纲及对应章节号，生成、编辑并确认。
6. 在“章节创作”设置本章目标字数及额外要求，点击“AI 创作 / 整章重写”。生成结果作为草稿保存，正式正文不被覆盖。
7. 可以直接编辑正文；在正文框选中一段文字，填写修改要求，点击“修改选中段落”，审阅后应用。应用建议后需要保存草稿。正文变化会使旧的修改建议失效。
8. 点击“确认定稿并更新记忆”，在确认窗口确认。正文先可靠保存，再提取记忆。前章未定稿时不允许生成或定稿后章。
9. 查看“小说记忆”的同步状态、逐章来源和 JSON 数据。可以手工修订摘要、人物状态、关系、时间线及伏笔，或按关键词检索正式章节全文。
10. 继续下一章；在“项目管理”导出全部正式章节的 Markdown。

AI 生成只读取正式设定和大纲；候选保存不代表生效。切换文档、章节或项目之前请保存编辑内容。浏览器断开时只有已保存内容保证恢复。

## 记忆冲突与恢复

记忆同步失败不会撤销或删除已保存的正文。界面显示失败原因，点击“重试 / 恢复记忆同步”继续处理；重启后也可以执行该操作。未同步前阻止新的章节 AI 生成，仍可查看与编辑。

如果模型发现设定冲突，候选记忆会保留在“小说记忆”中。对照正式设定与正文处理问题，编辑候选 JSON，并清空已解决的 conflicts，确认候选修订后重试同步。不要只清除错误提示而忽略实际矛盾。程序不会自动覆盖世界规则。

修改并重新定稿历史章节后，程序从该章开始依次重建记忆，保留后续正文并提示复核。修改正式设定也会触发记忆重建；修改较早章节的正式记忆则从后章重建。程序不自动重写已有后续正文。

## 文件与备份

```text
projects/<project_id>/
  CURRENT                     当前完整快照的版本 ID
  .write.lock                 写入互斥锁
  revisions/<version>/
    state.json                完整状态及 schema_version
    project.json              项目基本信息
    settings/                 正式设定、人物与势力
    outline/                  正式大纲、章节元数据
    drafts/                   候选设定、大纲和章节草稿
    chapters/                 正式章节完整 Markdown
    memory/                   逐章来源、摘要、人物、时间线和伏笔
    operations/current.json   定稿操作 ID 与同步进度
```

每次保存生成不可变修订，完成全部文件写入后才替换 CURRENT。应用只从 CURRENT 对应的 state.json 读取，避免混用新旧文件。目录中的其他 Markdown/JSON 是该修订的可读导出，不应直接编辑；在界面中编辑会生成新的完整修订。

备份时停止应用，复制整个数据目录，包括 CURRENT 和 revisions。历史修订不自动清理，数据量随保存次数增长。需要人工回滚时先备份，在停机状态下将 CURRENT 改为一个已完成且含有效 state.json 的历史修订 ID。中断时留下的未发布目录不作为正式数据读取。

本方案的原子替换主要防止进程中断造成半次保存，不能保证硬件损坏、磁盘故障或所有文件系统的断电行为；重要作品请另做备份。

## 验证与开发

```powershell
uv sync --locked
# 无本机 Edge 的环境先安装测试浏览器
uv run playwright install chromium
uv run pytest -q
Get-ChildItem tests/Verify-*.ps1 | ForEach-Object { & $_.FullName }
```

pytest 包含独立存储目录下的工作流测试和真实浏览器测试。Windows 优先用已安装的 Edge，其他环境使用 Playwright Chromium。浏览器测试会启动自己的随机本地端口，所有数据写到测试临时目录，不调用付费 API。

自动化五章测试采用演示模型，检查流程、上下文、来源和重启恢复。真实模型的中文创作质量、长篇一致性、字数达标率及至少五章人工审阅，需要在配置真实密钥后验收；它们不由固定示例测试代替。
