## 记忆整理失败的定位

曾出现模型返回 `incomplete / max_output_tokens`：输入为 3799 token，输出为 6000 token，其中思考占 6000 token，未返回可用记忆内容。这说明该次失败是输出预算耗尽，不是已经证实的余额不足、网络断开或超时。

处理原则：

1. 正式正文先可靠保存，记忆失败不会撤销定稿。
2. 记忆提取只发送完整定稿正文和必要的设定、人物与伏笔，按预算补充历史摘要。
3. 记忆整理与正文的思考强度独立；优先关闭记忆思考，避免盲目增加超时或预算。
4. 有设定冲突时保留候选，人工核对并解决后继续，不自动改写世界规则。
5. 后续 AI 创作等前文记忆同步完成，仍允许查看和手动编辑内容。

## 2026-11-25：更新后仍见相同报错的核查

- 当前代码默认及本地已加载设置均为记忆思考关闭；本地输出预算仍为 6000，总上下文预算为 24000。
- 最新失败依旧表现为 6000 输出 token 全用于思考，截图仍使用旧的“正文思考强度”指引。
- 按错误耗时反推，请求约在 10:29 开始，而最新桌面包在 10:30 才构建完成，疑似旧窗口或旧包仍在运行。现有日志未记录当次思考参数，不能仅凭时间认定最终原因。
- 建议保存并彻底退出旧窗口，通过项目根目录启动脚本重新启动，确认记忆思考关闭并保存，再重试整理记忆。
- 核查过程中没有重发真实小说；尚未确认用户项目的记忆已成功同步。仍失败时应对比新的错误编号、思考用量和实际输出，再判断参数兼容性或输出预算。
