# AI 网文写作 Agent — MVP 设计文档

**版本：** V0.1  
**项目阶段：** MVP  
**开发语言：** Python  
**核心目标：** 构建一个能够理解小说设定、规划剧情、持续创作章节并维护长期记忆的 AI 网文写作 Agent。

---

## 1. 项目概述

### 1.1 项目目标

开发一个面向长篇网络小说创作的 AI Agent。用户提供小说创作想法和基本要求后，Agent 能够协助完成小说设定、剧情规划、章节创作及小说记忆维护。

系统采用人机协作模式，由 AI 负责设定整理、剧情规划、正文生成和记忆更新，用户负责审阅、修改和确认。

MVP 阶段重点验证三个核心能力：

1. **持续创作：** 能够根据小说设定和章节大纲逐章生成正文。
2. **长期记忆：** 能够保存人物、世界观、剧情发展和未回收伏笔。
3. **剧情连贯：** 后续章节能够参考历史内容，尽可能避免人物、设定和剧情矛盾。

### 1.2 产品定位

本项目不是简单的 AI 文本生成器，而是具备项目管理、剧情规划、上下文记忆和连续创作能力的写作 Agent。

基本工作模式：

**用户构思 → AI 规划 → AI 创作 → 用户审阅 → 记忆更新 → 下一章创作。**

---

## 2. MVP 功能范围

第一版实现以下五个核心模块。

### 2.1 小说项目管理

支持创建、保存和加载小说项目。

基本功能：

- 创建小说项目。
- 编辑小说基本信息。
- 设置小说题材和类型。
- 设置目标读者。
- 设置叙事视角和语言风格。
- 设置目标总字数及章节目标字数。
- 保存和加载已有项目。

小说基本信息至少包含：

| 字段 | 说明 |
|---|---|
| project_id | 项目唯一标识 |
| title | 小说名称 |
| genre | 小说题材 |
| description | 小说简介 |
| target_readers | 目标读者 |
| narrative_perspective | 叙事视角 |
| writing_style | 写作风格 |
| target_total_words | 目标总字数 |
| target_chapter_words | 单章目标字数 |
| created_at | 创建时间 |
| updated_at | 修改时间 |

### 2.2 小说设定生成

根据用户提供的创作想法，AI 自动生成小说基础设定。

需要支持：

- 世界观和背景设定。
- 世界运行规则。
- 主角及主要人物设定。
- 人物关系。
- 势力和组织设定。
- 核心冲突与故事主线。

功能要求：

1. 用户输入初始创作想法。
2. AI 根据输入生成结构化设定。
3. 用户可以查看、编辑和重新生成。
4. 用户确认后保存为正式小说设定。
5. 后续创作自动读取已确认的设定。

不得将未经用户确认的生成内容直接覆盖已有正式设定。

### 2.3 剧情大纲生成

支持三个层级的剧情规划：

**（1）全书大纲**

- 小说核心主题。
- 故事背景和主线。
- 主角成长路线。
- 核心矛盾。
- 故事最终走向。

**（2）分卷大纲**

- 每卷核心目标。
- 主要剧情事件。
- 人物发展。
- 主要冲突。
- 阶段性结局。

**（3）章节大纲**

- 章节名称。
- 本章核心目标。
- 主要剧情事件。
- 人物参与情况。
- 本章冲突。
- 章节结尾及悬念。

功能要求：

- 支持 AI 生成各层级大纲。
- 支持用户手动编辑。
- 支持重新生成。
- 支持保存和加载。
- 章节创作时自动读取对应章节大纲。

### 2.4 AI 章节创作

这是系统的核心功能。

每次以单章为单位进行创作。

创作时，Agent 应读取：

1. 小说基础设定。
2. 相关人物设定。
3. 全书及当前分卷大纲。
4. 当前章节大纲。
5. 前文剧情摘要。
6. 相关人物当前状态。
7. 尚未回收的伏笔。
8. 用户本次额外创作要求。

基本功能：

- 根据章节大纲生成正文。
- 支持设置目标字数。
- 支持指定额外创作要求。
- 支持重新生成整章。
- 支持选中段落并要求 AI 修改。
- 支持用户直接编辑正文。
- 支持保存章节草稿。
- 支持章节定稿确认。

创作要求：

- 遵循已经确认的世界观和人物设定。
- 保持人物性格、语言风格和行为逻辑一致。
- 与前文剧情保持连贯。
- 避免重复描述和无意义情节。
- 尽可能满足章节目标字数。
- 章节结尾应符合当前剧情发展。

章节状态：

- 草稿：AI 已生成，但尚未确认。
- 已定稿：用户确认并正式保存。

未经用户确认的章节不得自动成为正式剧情记忆的依据。

### 2.5 小说长期记忆管理

这是本项目的重要技术模块。

采用结构化记忆与历史章节检索相结合的方式，维护长篇小说的连续性。

需要维护四类记忆：

| 记忆类型 | 主要内容 |
|---|---|
| 世界观记忆 | 世界背景、规则、修炼体系等 |
| 人物记忆 | 人物性格、能力、关系、当前状态 |
| 剧情记忆 | 已发生事件、重要情节、故事时间线 |
| 伏笔记忆 | 已埋设伏笔、出现位置、回收状态 |

每章定稿后，Agent 自动执行：

1. 生成本章剧情摘要。
2. 提取新增人物及人物变化。
3. 更新人物状态和关系。
4. 提取重要剧情事件。
5. 更新故事时间线。
6. 记录新埋设的伏笔。
7. 更新已有伏笔的回收状态。

记忆管理要求：

- 原始章节正文必须完整保存。
- 记忆摘要不能代替原始章节。
- 支持查看和手动修改记忆。
- 支持根据创作需要检索历史章节。
- 不得擅自修改已经确认的世界观设定。
- 发现设定冲突时，应提示用户，而不是自行覆盖原有设定。

记忆更新应与章节定稿关联，避免草稿和重新生成的内容污染正式记忆。

## 3. Agent 工作流程

系统采用单主 Agent 协调的工作流，不在 MVP 阶段引入多个独立 Agent。

### 3.1 小说初始化

1. 用户创建小说项目。
2. 用户填写基本创作要求。
3. Agent 生成小说基础设定。
4. 用户审阅和确认。
5. Agent 保存正式设定。

### 3.2 剧情规划

1. Agent 根据小说设定生成全书大纲。
2. 用户审阅和确认。
3. Agent 根据全书大纲生成分卷大纲。
4. 用户选择当前创作分卷。
5. Agent 生成对应章节大纲。
6. 用户审阅和确认。

### 3.3 章节创作

1. 用户选择待创作章节。
2. Agent 读取小说设定、章节大纲及相关历史记忆。
3. Agent 生成章节正文。
4. 用户审阅正文。
5. 用户可以修改、要求重写或确认定稿。
6. 用户确认后保存正式章节。
7. Agent 自动更新小说记忆。
8. 进入下一章创作。

### 3.4 工作流原则

- 用户拥有最终决定权。
- 重要设定和剧情大纲需要用户确认。
- 章节可以多次修改和重新生成。
- 只有定稿章节进入正式记忆。
- 每个阶段的结果都必须持久化保存。
- 发生异常时，不应丢失已经保存的小说内容。

## 4. 数据存储与项目结构

MVP 采用本地文件存储，使用 Markdown 保存文本内容，JSON 保存结构化数据。

不引入复杂数据库和向量数据库。

### 4.1 推荐项目目录

```text
Novel_Project/
├── project.json
│
├── settings/
│   ├── worldbuilding.md
│   ├── characters.json
│   └── factions.json
│
├── outline/
│   ├── main_outline.md
│   ├── volume_01.md
│   └── chapters.json
│
├── chapters/
│   ├── chapter_001.md
│   ├── chapter_002.md
│   └── chapter_003.md
│
└── memory/
    ├── story_summary.md
    ├── timeline.json
    ├── character_states.json
    └── foreshadowing.json
```

以上为单个小说项目的数据目录。系统应支持管理多个小说项目，每个项目具有独立的数据目录。

### 4.2 数据管理要求

- 项目创建时自动建立必要目录。
- 文件采用 UTF-8 编码。
- JSON 文件应保证格式合法。
- 保存操作应避免意外覆盖已有数据。
- 支持项目重新加载。
- 支持章节按编号排序。
- 支持 Markdown 导出。

## 5. 技术架构

### 5.1 基本技术选型

| 模块 | 技术方案 |
|---|---|
| 开发语言 | Python |
| Agent | 单 Agent + 工作流编排 |
| 大语言模型 | 通过 API 接入一种模型 |
| 数据存储 | Markdown + JSON |
| 用户界面 | 本地 Web UI |
| 内容导出 | Markdown |

具体 Web UI 框架由开发阶段确定，优先考虑实现简单、交互清晰和便于后续扩展的方案。

### 5.2 软件模块划分

建议按照以下职责划分代码：

- `app/`：程序入口及界面。
- `agent/`：Agent 核心逻辑和创作工作流。
- `llm/`：大模型 API 调用及配置。
- `prompts/`：设定生成、大纲生成、章节创作、记忆更新等提示词。
- `memory/`：小说记忆管理和历史内容检索。
- `storage/`：小说项目及文件读写。
- `models/`：项目、人物、章节和记忆的数据模型。
- `tests/`：单元测试及功能测试。

模块之间应保持职责清晰，避免将模型调用、文件读写和界面逻辑混合在一起。

### 5.3 大模型调用

- API Key 通过环境变量或本地配置文件读取。
- 不得将 API Key 硬编码在源代码中。
- 模型名称和 API 地址应支持配置。
- 统一处理模型调用、超时、异常和返回结果。
- 对结构化生成结果进行格式校验。
- 避免将大段历史章节无差别地全部放入上下文。

## 6. 用户界面

MVP 采用简洁的本地 Web 界面。

建议划分为四个主要区域：

**（1）小说项目管理**

- 小说项目列表。
- 新建项目。
- 加载项目。
- 编辑小说基本信息。

**（2）小说设定与大纲**

- 世界观编辑。
- 人物设定管理。
- 全书大纲查看与编辑。
- 分卷和章节大纲管理。

**（3）章节创作**

- 当前章节信息。
- 章节大纲展示。
- AI 创作要求输入。
- 正文编辑区域。
- 生成、重新生成和保存按钮。
- 定稿确认操作。

**（4）小说记忆**

- 剧情摘要。
- 人物状态。
- 故事时间线。
- 伏笔列表。
- 历史章节查看。

界面以实用为主，暂不追求复杂的视觉效果。

## 7. MVP 验收标准

第一版完成后，应通过以下测试。

### 7.1 项目管理测试

- 能够创建多个小说项目。
- 能够保存和重新加载项目。
- 项目之间的数据相互独立。

### 7.2 小说设定测试

- 能够根据用户输入生成基础设定。
- 能够编辑并确认设定。
- 确认后的设定能够正确保存和读取。

### 7.3 剧情规划测试

- 能够生成全书、分卷和章节大纲。
- 能够编辑和保存大纲。
- 章节大纲能够正确关联对应章节。

### 7.4 章节创作测试

- 能够根据章节大纲生成正文。
- 能够读取小说设定和历史记忆。
- 能够重新生成章节。
- 能够修改指定段落。
- 能够保存草稿和定稿。

### 7.5 长期记忆测试

使用同一个小说项目连续创作至少 5 章，检查：

- 是否能够记住主要人物及其特征。
- 是否能够保持世界观设定一致。
- 是否能够正确引用前文重要事件。
- 是否能够更新人物状态。
- 是否能够记录和维护伏笔。
- 是否能够在重新启动程序后恢复小说记忆。

### 7.6 数据安全测试

- 草稿不会自动覆盖正式章节。
- 未定稿章节不会污染正式记忆。
- 程序重启后能够恢复已保存的数据。
- 模型调用失败时不会破坏已有文件。

## 8. MVP 暂不实现的功能

为控制第一版开发规模，以下功能暂不纳入：

1. 多 Agent 自主协作。
2. 自动搜索网络小说素材。
3. 自动投稿和发布。
4. AI 自动生成小说封面。
5. 向量数据库和复杂 RAG 系统。
6. 多模型智能路由。
7. 模型微调和私有化训练。
8. 自动生成整本小说。
9. 多用户协作和云端同步。
10. 复杂的版本管理系统。

后续根据实际使用效果再决定是否增加。

---

## 9. 开发原则

1. **先实现完整闭环：** 优先保证从创建小说到连续创作、记忆更新的完整流程能够运行。
2. **保持简单：** MVP 不引入不必要的框架和复杂架构。
3. **数据持久化优先：** 小说设定、章节正文和记忆必须能够可靠保存。
4. **人机协作：** 关键内容由用户确认，AI 不得擅自修改正式内容。
5. **模块化设计：** 为后续增加智能审核、多 Agent 协作和高级记忆机制预留扩展空间。
6. **可测试：** 核心模块应具备独立测试能力。
